How each pipeline behaves

The Real time tab offers three live pipelines. They all capture microphone audio the same way — a browser AudioWorklet resamples the mic to 16 kHz mono PCM16 and streams it over a WebSocket. The server holds the Azure credentials (keyless Entra ID), so no token ever reaches the browser. What differs is how the audio becomes text.

🎙️ Microphone → AudioWorklet
16 kHz PCM16 → WebSocket

MAI Near-real-time ≈ 8-second cadence

Server buffers your speech and, every ~7 seconds of new audio (plus 1 second of context), wraps a window as a WAV and sends it to MAI-Transcribe-2 through the fast-transcription REST API. Completed phrases are appended in order; the overlapping context is dropped by comparing timeline offsets, so nothing is duplicated. You get MAI's full multilingual accuracy, refreshed every few seconds — not word by word.

PCM buffer → Rolling 8s
WAV window → MAI REST
enhancedMode → Offset de-dup → Ordered text 
# realtime.py — commit a window every ~7s of new audio
while rb.has_window():
    pcm, start_ms, boundary = rb.take_window()
    raw = await mai_client.transcribe_wav(mai_client.pcm16_to_wav(pcm), definition)
    phrases = filter_new_phrases(mai_client.normalize(raw)["phrases"], start_ms, boundary)
    await emit({"type": "chunk", "phrases": phrases})
    rb.advance()
  • Latency ~8s per update
  • Interim words no
  • Speaker labels off
  • Best for highest MAI accuracy, Hinglish
Standard Realtime instant interim words

PCM is pushed straight into the Azure Speech SDK continuous recognizer. It emits recognizing events with interim words as you speak, then a recognized event with the finished sentence when you pause. This is true streaming — lowest latency — and is English-first with light multilingual auto-detect.

PCM frames → PushAudioInputStream → Speech SDK
continuous → recognizing → partial
recognized → final 
# realtime.py — bridge SDK callbacks to the WebSocket
recognizer.recognizing.connect(lambda e: emit_ts({"type": "partial", "text": e.result.text}))
recognizer.recognized.connect(lambda e: emit_ts({"type": "final", "text": e.result.text}))
recognizer.start_continuous_recognition()
  • Latency instant (interim)
  • Interim words yes
  • Speaker labels n/a
  • Best for live captions, dictation
Hybrid live now, MAI-clean on stop

Hybrid runs the Standard recognizer for instant captions and buffers the whole recording. When you press Stop, the full clip is sent once to MAI-Transcribe-2 and the live transcript is atomically replaced by the cleaner MAI result — coherent language detection, better boundaries, and optional speaker labels. If that final pass fails, the live text is kept as-is.

While recording
Mic → PCM → Speech SDK → Interim captions
On stop
Full recording → MAI REST → Replace transcript 
# realtime.py — interim live, then one MAI pass replaces everything
await _run_standard(...)          # streams partial/final while recording
raw = await mai_client.transcribe_wav(mai_client.pcm16_to_wav(full_recording), definition)
await emit({"type": "replacement", "result": mai_client.normalize(raw)})
  • Latency instant + final polish
  • Interim words yes
  • Speaker labels yes (final)
  • Best for demos needing speed & accuracy
End of call English transcript + summary

Live and batch transcripts keep every word in the language it was spoken (English, Hindi, Marathi…). When the call ends, the final transcript is sent once to an Azure OpenAI chat deployment, which returns two extra outputs: a full English transcript (Hindi/Marathi translated by meaning, speaker labels kept) and a short summary. For example, "I am buying das hazar ka stock kal" becomes "I will buy ten thousand rupees' worth of stock tomorrow." The original transcript is never modified.
